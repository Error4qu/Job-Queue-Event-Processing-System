⚙ Bottleneck Diagnosis & Fix Suggestions

  • Tomcat thread pool: Add server.tomcat.threads.max=400 to application.properties
  • HikariCP connections: Add spring.datasource.hikari.maximum-pool-size=30
  • Windows port exhaustion: Normal for loopback tests — set net.ipv4.tcp_tw_reuse=1 or use Linux
  • Kafka producer batching: Tune spring.kafka.producer.batch-size and linger.ms for higher throughput
  • Rate limiter: Your current 5-RPS/type limit will always throttle bursts — intended behaviour

Architecture Notes & Scaling Recommendations

🔮 Production Scaling Roadmap

  • Kafka Partitions: Scale from 1 → N partitions and match consumer concurrency to enable horizontal processing
  • Redis Cluster: Move from single Redis to Redis Cluster for HA rate-limiting and delay queue at scale
  • MySQL Read Replicas: Offload GET /jobs/{id} and stats queries to read replicas
  • API Instances: Stateless Spring Boot app — deploy behind load balancer; use leader election for Watcher/Dispatcher
  • Observability: Add Micrometer → Prometheus → Grafana for job throughput, failure rate, and queue depth dashboards
  • DLQ: Implement Dead Letter Queue for jobs that exhaust all retries — prevents silent data loss
